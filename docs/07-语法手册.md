# RScell 语法手册（逐词）

> 面向已经打开 `.rscel` 文件的人。每个语法词都给四件事：**怎么写 → 是什么意思 →
> 编译成什么 Rust → 代价与误用后果**。性能数字全部来自 `docs/04-性能基准报告.md`
> 的实测（对 `fn_hand` 手写基线，同组 rustc flag，交错采样取最小值），不是估计。
>
> 一句话定位：**Cell 是业务流程节点，`jump` 是节点之间的拓扑边，函数体是 Rust 透传**。
> 编译器把整套编排翻译成一个 `.rs` 文件，`rustc` 直接编译，**生成物零外部依赖**。

---

## 0. 一个最小完整程序

```rscel
entry main;                 // 指定入口 Cell（不写就必须有个叫 main 的 Cell）

cell main;                  // 声明一个 Cell（流程节点）
receive();                  // 入口契约：这个节点接收哪些数据（这里没有）
let five: i64 = 5;          // Rust 透传语句，原样进生成物
jump fact go with(five -> n, 1i64 -> acc);   // 转移给 fact，并携带数据

cell fact;
receive(n: i64, acc: i64) as (cur, sum);     // 接收两个键，并把它们改名为 cur/sum
let next = cur - 1;
let next_acc = sum * cur;
jump loop fact when next > 0 go with(next, next_acc);  // 原地循环（不是转移，不新建实例）
out(next_acc);              // 调试打印
exit go with(next_acc -> result);              // 正常出口，产出返回包
```

编译并运行：

```bash
rscel build prog.rscel -o prog --release && ./prog     # 输出 120
```

## 1. 声明类关键字

### `cell`
**写**：`cell <名字>;` 后面必须紧跟 `receive(...)`，再跟若干语句。
**意**：声明一个流程节点。Cell 不是函数调用栈上的一层，而是**拓扑上的一个顶点**：
它自己决定何时终止（`exit` / `die` / 无条件 `jump`）。
**生成**：一个 `fn cell_<名>(<带类型的形参>) -> Option<Ret_<名>>`。`Option` 是因为
Cell 可能 `die`（`None` = 没有产出返回包）。
**代价**：同步 Cell 之间是普通函数调用，实测与手写打平（`loop_sum` 99.24%）。
**误用**：`cell a;` 后没有 `receive` → **E034**。

### `entry`
**写**：`entry <cell 名>;`（至多一条）。
**意**：指定程序从哪个 Cell 开始。省略时找 `cell main`。
**生成**：`fn main()` 里先收 `std::env::args().skip(1)`，再按入口 Cell 的 `receive`
形参类型逐位转型：`Vec<String>` 得整个 argv；`String` / `i64` / `u64` / `usize` /
`f64` / `bool` / `char` 走 `parse()`；其它类型取 `Default::default()`（argv 承载不了）。
**误用**：没有任何入口 → **E020**；写多条 `entry` → **E037**。

### `receive`
**写**：`receive(<键>[: <类型>], ...) [as (<别名>, ...)];`
**意**：**显式入口契约**。这个节点接受哪些数据键、每个键的 Rust 类型是什么。
三种形态：

| 形态 | 含义 |
| --- | --- |
| `receive(n: i64)` | 键名 = 变量名 |
| `receive(n: i64, acc: i64) as (cur, sum)` | 键名与变量名分离（便于读） |
| `receive(g1.W1.d, g1.W2.d) as (a, b)` | **多包接收**：从并发组的第 1、2 个实例返回包里取 `d` |

**生成**：形参 → `let v_<序号>: <类型> = <形参>;`，之后所有透传文本里的别名都会被
重写成 `v_<序号>`（见 §5 `as`）。多包接收的键**不在入口绑定**，而是在 `jump sync`
之后才解包（S4 late binding）。
**类型从哪来（D2，绝不猜）**：注解优先 → 由所有入边实参反向传播 → 由字面量/运算符
推导；三条路都走不通就发 `compile_error!` 明确要求你补注解。
**误用**：某键在所有入边都没被供给 → **E042**；多源组里写了裸键 → **E043**。

### `as`
**写**：`receive(...) as (a, b, c)`；也可写在单个键上 `receive(order -> ord)`（等价形态）。
**意**：给接收槽位起**局部变量名**。键名是拓扑上的公共契约，别名是这个节点内的私有名。
**代价**：零。只是重命名，编译后就是 `v_a` 这样的绑定。

## 2. 出口类关键字（一个 Cell 只能有一个出口）

### `exit go with`
**写**：`exit go with(<表达式> -> <键>, ...);`，键可省略时 `x -> x`（`x` 必须是简单标识符）。
**意**：正常收敛，产出一个返回包。
**生成**：`return Some(Ret_<Cell> { 键: 表达式, ... });`
**误用**：非标识符表达式又不写 `-> 键` → **E040**；`exit` 之后还挂着语句 → **E010**
（那段代码永远不会执行，编译器不会替你把告警留到 rustc）。

### `die`
**写**：`die;`
**意**：销毁本实例，**不产出任何返回包**，本地变量与别名全部 drop。
**生成**：`return None;`
**后果**：父侧如果正等着这个包的某个键 —— 契约期就被 **E042/E044/S3** 拦住，
不会给你 `Default::default()` 兜底（这是冻结决策：宁可报错也不给你假数据）。
**注意**：规范文档里出现过的 `die when <cond>;` **不是合法语法**（parser 报 E030）；
要条件终止就写 `jump ... when ...;` + 兜底 `die;`。

### `out`
**写**：`out("文本 ", 表达式, ...);`
**意**：调试打印，**不是出口**，不影响收敛检查。
**生成**：`println!("{}", ...)`（多参按 `"{} {} "` 形式）。当前 release 也保留。

## 3. `jump` 的五种形态（这节是全语言的核心）

固定段序（写错顺序就是语法错误）：

```
jump [loop|recurse|and] <目标[, 目标…]> [when <条件>]
     [go with | read with | force go with | force read with] (<实参…>)
     [return(<键> -> <别名>, …)]
     [over <集合> [|> filter(…) |> map(…) |> flat_map(…) |> take(n) |> skip(n)] …]
     [concurrent_limit = <表达式>] [group <名>] ;
```

| 形态 | 新建实例 | 是否出口 | 生成形状 | 实测代价 |
| --- | --- | --- | --- | --- |
| `jump T` | 是 | **是**（本实例终止） | 直接调用 `cell_T(按 T 声明顺序的实参)` | 与手写函数调用打平 |
| `jump loop T` | 否 | 否 | 一个 `loop { }`，按**位置**刷新本 Cell 的 `v_<id>` | 归约循环可向量化，见下 |
| `jump recurse T` | 是 | 否 | 紧邻 `jump sync` 时 = 内联直接调用；否则进组 spawn | 内联路径零额外开销 |
| `jump and T1, T2` | 每目标各 N 个 | 否 | 一个 OS 线程池（supervisor）+ 组句柄 | `pipeline_and` 100.49% |
| `jump sync g` | 否 | 否 | `Condvar` 阻塞等待 + 解包多包 receive | 见 §3.5 |

### 3.1 `jump T`（plain，转移式出口）
**意**：把执行权交给 `T`，本实例到此结束；`T` 自己用它的 `exit` 收敛。
**为什么重要**：它**不等待**、**不回传**。所以以下都非法（**E046**）：
`return(...)`、`group`、`over`、`concurrent_limit` —— 挂在出口上的这些段落没有任何
消费者。想拿返回值请改写 `jump recurse`。

### 3.2 `jump loop T`（原地循环）
**意**：`T` 必须是**当前 Cell**（否则 **E011**），实参**按位置**刷新 receive 列表
（所以实参个数必须等于 receive 键数，否则 **E041**）。
**生成**：
```rust
loop {
    let next = v_a - 1;          // 循环内新鲜绑定（DSL 里 jump 之前写的 let 会被接管）
    let next_i = v_b + 1;
    if !(next <= limit) { break; }
    v_a = next; v_b = next_i;
}
```
**性能（关键结论）**：`loop_sum`（5000 万次纯算术归约）实测比值 **1.0076 → 99.24%**,
`loop_sum_opaque` **0.9871 → 101.31%**，即与"把同样的循环写在一个普通 `fn` 里"的手写
基线**打平**。曾经测出的 40–55% 差距，根因是**基线不公平**（对照程序把循环写在
`fn main` 里，LLVM 因而已先做了向量化），不是调用约定的成本 —— 这条已经用
`fn_hand` 第三基线纠正，见 `docs/06-控制变量实验.md`。

### 3.3 `jump recurse T`（真递归 / 子实例）
**意**：创建一个全新子实例，父实例**等它收敛**后继续（所以它不是出口）。
**`return(<键> -> <别名>)`**：把子实例返回包里的键搬进父侧变量。别名**必须**在本
Cell 里已声明成 `let mut 别名: Option<T> = …;`（**E036**）—— 因为子实例可能 `die`，
类型只能是 `Option`；生成的是**赋值**，所以必须 `mut`。
**`group g`**：这个子实例归入组 `g`（§6.3 明确 recurse 也建组，因此 `jump sync g` 合法）。
**两条生成路径（D3 冻结决策）**：
```rscel
jump recurse fact go with(n - 1 -> n) return(product -> sub) group r1;
jump sync r1;          // 紧邻 sync ⇒ 内联：let __rsc_sub = cell_fact(…);  零 spawn
```
若下一条语句不是 `jump sync r1`，则改为进组 spawn，父实例立即继续，别名**延迟**到
`jump sync` 时绑定（值在那之前根本不存在）。
**限制**：同一个子实例返回包**不能**既被 `return(...)` 又被 `receive(g.W1.键)` 读走
（**E047**）—— Rust 的所有权只允许消费一次，两个读者必然有一个拿到假数据。

### 3.4 `jump and T1, T2 …`（并行派生）
**意**：对每个目标各派生实例，全部归入 `group`。两种来源：
```rscel
jump and worker over items |> filter(|f| f.0 > 0) concurrent_limit = 8 group g1;  // 每元素一个实例
jump and w1, w2 go with(0 -> x) group g1;                                          // 两个目标各一个实例
```
**多目标时的槽位映射**：`g1.W1` = 第 1 个目标，`g1.W2` = 第 2 个（入组顺序，§6.4）。
**单目标 + over**：`g1.Wk` = 集合第 k 个元素的实例。
**`concurrent_limit`**：恒为**上限**。不写时默认 `available_parallelism()`（实测过
"100 万元素 → 47,724 线程 / 828MB / 150 秒"的教训，绝不按元素数开线程）；
写成数字面量却不合法 → **E039**。
**依赖检查**：带 `concurrent_limit` 且多目标时，若目标之间可（传递）跳转 → **E050**
（§7.3 要求子实例完全独立；父侧 `read with` 下发同一个 Arc 是允许的例外）。
**没写 group 名**时是合法的 fire-and-forget（并发发通知），但结果不会被任何人接收 ——
拓扑图会明确标注它。

### 3.5 `jump sync g`
**意**：等待组 `g` 全部子实例完成，之后才能读 `g.Wk.键`。
**约束**：组必须由**本 Cell** 更早的 `jump and` / `jump recurse` 创建（否则 **E035**），
同一组只能 sync 一次（否则也 **E035**）。
**D5 槽位语义**：多包 receive 声明的槽位数 = 最大 `W<n>`（跳号会补空槽，不会越界）；
槽位多于静态元素数 → **E045**；元素多于槽位 → **W002**（多余实例结果按 D4 增量回收丢弃）。
**性能**：`pipeline_and`（20 万元素、8 线程、跨 Cell 转移）实测 **100.49%**。

## 4. 数据传递与所有权

### `go with`
**意**：**独占所有权**转移 —— 值搬到目标 Cell，父侧从此不能再用它（再 move 或修改
会触发 **E061/E062**）。

### `read with`
**意**：**只读共享**。`read with(x)` 生成 `Arc::clone(&x)`；如果 `x` 还不是 Arc，编译器
在第一次发送前插入一次 `Arc::new(x)` 提升，此后所有接收方共享**同一份**原始数据
（引用计数 +1，不是拷贝数据）。
```rscel
cell b;  receive(big_data: Arc<String>);   // 接收端注解必须是 Arc，否则 E037
```
**冻结**：被 `read with` 分发出去的变量进入 **Frozen** 状态，后续不能 `go with`（move）
也不能修改（**E061**）。
**小 POD 禁止**：`i64/u64/f64/bool` 之类用 Arc 得不偿失 → **E063**；确实要用就
`force read with`（**W060** 仍会建议你改 `go with`）。
**性能**：`read_share`（5 万实例共享一个 2.5KB payload）实测 **100.40%**。

### `force go with` / `force read with`
绕过某些启发式判定的显式声明，语义同上，但会留下警告（表明你在对抗编译器的建议）。

## 5. `over` 管道

`|> filter(|x| …)` / `|> map(|x| …)` / `|> flat_map(|x| …)` / `|> take(n)` / `|> skip(n)`
按顺序编译成 Rust 迭代器适配器链。**闭包必须是纯函数**：里面出现 DSL 关键字
（`jump` / `exit` / `die` / `receive` …）→ **E080**。集合属于父实例，管道在 supervisor
线程**外**求值，所以父 Cell 之后还能用这个集合。

## 6. `extern rust`（逃逸口）

```rscel
extern rust {                      // 顶层：直接成为生成物里的 Rust item
    async fn rsc_slow(x: i64) -> i64 { x * 1 }
}

cell w;
receive(x: i64);
extern rust { let y: i64 = rsc_slow(x).await; };   // Cell 内：是一条“语句”
exit go with(y as i64 -> d);
```

规则：Cell 内它是**语句**、顶层它是 **item**（D6）。块内**禁用 DSL 关键字**（§9.3），
但 receive 别名照常按 §10.3 重写 —— 否则别名在块里根本用不了。块内代码原样进生成物，
所以**它的 Rust 报错不做 DSL 反映射**（RSC-E901，位置就是你写的那段 Rust）。
顶层裸写的 Rust item（`use` / `struct` / `impl` / `fn`）等价于隐含的 `extern rust {}`。
性能上这是最快的路径：热点直接手写原生 Rust，**100%**（转译恒等）。

注意一个已知推导缺口：`exit go with(fast_mul(a, b) -> x)` 这类**函数调用表达式**的返回
类型，D2 目前没有推导来源，需要写 `as <类型>` 消歧（见 `docs/05` P0）。

## 7. 性能：哪些形状值 100%，哪些会掉

**状态：已复测（空闲机器、20× 工作量、21 轮交错采样）**。5 个场景对手写基线落在
**96%–104%**：转译本身不产生结构性开销，剩余差异与场景的调度/状态机噪声同量级
（复现带 ±1.4%~±7.3%，比门禁余量宽，所以这里只给区间、不给"达标"结论）。
维护者裁定：≥97% 即为可接受的转译代价，99% 作为持续优化方向。
## 7. 性能：哪些形状值 100%，哪些会掉

> **状态：待复测**。下表数字取自 `docs/04-性能基准报告.md`，而那批测量是在**背景虚拟机
> 持续波动负载**下跑出来的 —— 复现带只有 ±1%~±4%，这种精度的"打平"结论在负载抖动下
> 不成立。空闲机器上 `bash scripts/bench/run.sh` 重跑之前，请把这张表读成
> "**形状之间的相对代价排序**"（恒等 < 直接调用 < Arc 原子 < async 状态机），
> 而不是绝对达标证明。

| 你写的形状 | 生成物 | 实测/结论 |
| --- | --- | --- |
| 普通 `let`、算术、分支、函数调用（透传） | 逐字透传 | **恒等，100%** |
| `extern rust { … }` 手写热点 | 原样插入 | **100%**（转译不存在） |
| `jump`（plain）串行转移 | 直接函数调用 | **打平**（S2 类型化调用约定；对比类型擦除 Packet 慢 69–89×，已否决） |
| `jump loop` 数值热循环 | `loop {}` + 位置刷新 | **99.24%–101.31%**（可向量化；前提是别在循环携带变量上做副作用重算） |
| `jump and` + `concurrent_limit` | OS 线程池 + `VecDeque` 出队 | **100.49%**（同步 worker 不经过任何 future） |
| `read with` 多层共享 | `Arc::clone` | **100.40%**（原子计数是共享语义的固有成本，不是转译成本） |
| `jump recurse` 内联路径 | 直接调用 | 打平（零 spawn、零装箱） |
| **含 `.await` 的 Cell** | `async fn` + `__rsc_block_on` | **99.01%** ← 目前最弱的一格，差距来自自研 executor 的 waker/poll 路径 |
| 超微小 Cell 高频派生且无法内联 | 每实例一次函数调用 | 掉点：调用开销恒定但相对值大 —— 业务上应该合并这类 Cell |
| 类型擦除 `Packet`（`--dyn-packets`，默认关闭） | `Box<dyn Any>` | 慢 **69–89×**，仅用于对照实验，别用于生产 |

一句话：**DSL 的拓扑结构本身不产生开销**；开销只会来自你显式要求的东西（`Arc` 原子、
线程池、`async` 状态机）。性能数字全部可在 `bash scripts/bench/run.sh` 复现。

## 8. CLI 速查

| 命令 | 作用 |
| --- | --- |
| `rscel check <f.rscel>` | 只做 parse + C1–C8 静态检查，输出诊断与调用链路 |
| `rscel graph <f.rscel> [--mermaid]` | 拓扑链路报告（文本缩进树 / mermaid `graph TD`） |
| `rscel trace <f.rscel> [--max-items N]` | 干跑模拟消息流转（**不保证与真实执行数值一致**，`when` 只解释字面量与简单标识符比较，解释不了标 `(uninterpretable)`） |
| `rscel build <f.rscel> -o <out> [--release\|--debug]` | 全流水线：生成 `.rs` + `.map.json` + `rustc` 编译；rustc 错误自动反映射到 DSL 行列 |
| `rscel edit [f.rscel] [--port 8421]` | 本地 127.0.0.1 编辑器：源码高亮、实时诊断、可点击的 Cell 拓扑图、trace 时间线回放、一键构建运行、查看生成物 |

退出码：**0** 成功 / **1** 前端错误（parse、check）/ **2** rustc 编译错误 / **3** 参数或 IO 错误。

## 9. 错误码索引（按主题）

- 语法与骨架：E030–E034、E037、E020
- 契约（键对不对得上）：E040 键名缺失 · E041 loop 元数 · E042 键无来源 · E043 多源裸键 ·
  E044 包名/键名越契约 · E045 槽位与元素数不符 · E046 出口 jump 挂 `return` ·
  E047 返回包被消费两次
- 收敛：E010（分支未收敛 / 出口后有死代码）· E011（loop 目标非自身）· E014（无出口死循环）
- 类型：E036（`return` 别名形状）· E037（`read with` 接收端非 `Arc`）· E038（推不出类型）
- 并发：E035（group 未创建/重复 sync）· E039（限流字面量非法）· E050（子实例不独立）
- 所有权：E060–E064（move/Frozen/Arc 误用）· W060（POD 上 `force read with`）
- 其他：E070 遮蔽 · E080 `over` 闭包非纯 · E090 `extern rust` 边界 ·
  **RSC-E900/E901** rustc 错误（前者已映射回 DSL 行，后者在你写的 Rust 块内）

## 10. English keyword reference

The Chinese sections above are authoritative; this table is the 1:1 English counterpart, so
the language can be read without Chinese. Columns: **keyword / meaning / generated Rust /
cost & misuse diagnostics**.

| Keyword / form | Meaning | Generated Rust | Cost & errors |
| --- | --- | --- | --- |
| `cell N;` | declare a flow node (a topology vertex, not a stack frame) | `fn cell_N(<typed params>) -> Option<Ret_N>` | free; missing `receive` -> E034 |
| `entry N;` | program start node; falls back to `cell main` | called from `fn main`, argv cast per parameter type | no entry -> E020; two entries -> E037 |
| `receive(k: T, ...) as (a, b)` | explicit input contract; `as` renames slots locally | parameters plus `let v_<i>: T = a;`, later text rewritten to `v_<i>` | key with no producer -> E042; bare key in a multi-source group -> E043 |
| `receive(g.W1.k: T)` | multi-packet receive: field `k` of instance #1 of group `g` | unpacked **after** `jump sync g` (late binding) | slots > static element count -> E045; elements > slots -> W002 |
| `exit go with(e -> k, ...)` | normal convergence, produces a return packet | `return Some(Ret_N { k: e, ... });` | non-identifier expr without `-> k` -> E040; statements after it -> E010 |
| `die;` | destroy this instance, **no** return packet | `return None;` | a parent reading a key killed by `die` is rejected at contract time (S3), never silently defaulted |
| `out(a, b);` | debug print, **not** an exit, ignored by convergence checks | `println!("{}", ...)` | free |
| `jump T go with(...)` | tail transfer; this instance ends, the target's result is discarded | direct call, arguments ordered by the **callee's** receive list | carrying `return/group/over/concurrent_limit` -> E046 |
| `jump loop T when c go with(...)` | in-place iteration; arguments refresh receive slots **by position** | `loop { let x = ...; if !(c) { break; } v_0 = x; ... }` | target must be self -> E011; arity mismatch -> E041 |
| `jump recurse T ... return(k -> a) group g` | child instance, parent waits for it; not an exit | adjacent `jump sync` => inline call + tuple destructure into `a`; otherwise a one-element group on a worker thread | `a` must be a prior `let mut a: Option<T>` -> E036; `k` absent from T's outputs -> E044; consuming the same packet via both `return` and `g.W1.k` -> E047 |
| `jump and T1, T2 ... over C [\|> map(f)] [concurrent_limit = n] group g` | parallel derivation; one sub-group per target | bounded OS-thread pool + `__RscGroup<T>` handle; the `over` pipeline is evaluated in the parent | siblings must be independent when `concurrent_limit` is present -> E050; illegal literal limit -> E039; omitting `group` = fire-and-forget (results unread) |
| `jump sync g;` | join the group and unpack `g.W<n>.key` | blocking `Condvar` wait + per-slot unpacking (missing slot binds `Default`, `die` arm panics with S003) | group not created in this cell, or synced twice -> E035 |
| `go with` | exclusive ownership transfer (move) | value passed by move | reuse after move, or an `Arc` in `go with` -> E060-E064 |
| `read with(x)` | read-only sharing | `Arc::clone(&x)`, with a one-shot `let x = Arc::new(x);` promotion | receiver annotation not `Arc<T>` -> E037; POD payload -> E063 (`force read with` -> W060); moving a frozen variable later -> E061 |
| `over C \|> filter/map/flat_map/take/skip` | bulk derivation over a collection | iterator adapter chain, built outside the worker thread | non-pure closure (DSL keywords inside) -> E080 |
| `concurrent_limit = n` | hard upper bound on simultaneous instances | thread count `min(n.max(1), items)`; default `available_parallelism()` | never one thread per element (measured 47,724 threads / 828 MB / 150 s on 1e6 items before the fix) |
| `extern rust { ... }` | escape hatch: raw Rust | top level becomes items; inside a cell becomes statements (aliases are still rewritten) | errors inside are reported as RSC-E901 **without** DSL remapping; DSL keywords inside are rejected -> E090 |
| `if` / `for` / `match` blocks containing DSL | control flow with real DSL statements nested inside | verbatim block text with `{}` preserved and nested statements generated | nested conditions are treated conservatively for convergence checking |

Diagnostics print as `RSC-Exxx` / `RSC-Wxxx` with file, cell, `line:col` and an actionable
detail. Exit codes: 0 ok, 1 frontend (parse/check), 2 rustc, 3 argument or IO.
